## Gotchas a fresh session would get wrong (max 8, only things still true)
- Start everything with tools/jarvis_trial/start_jarvis_trial.ps1 (speaker, relay with --speak, Jarvis, closes the "Model recommendations" notice, hides the face). Never start Jarvis.exe alone (localFiles can delete files). Jarvis's own voice is ON but muted per app by the speaker service so its follow-up window opens when Daniel finishes. Jarvis sometimes is simply not running (state file %TEMP%\jarvis_state says "asleep"): check before a demo. To load a changed relay or Jarvis config, stop the relay python processes (and Jarvis.exe for config) first, then run the script.
- C:\Users\Ivan\.config\jarvis\config.json holds the Gemini key: never print, copy or commit it; JarvisTrial\config_*.json backups hold it too (config_pre_followup12.json is the newest). Scripts may read it in-process (tests do), never echo it. Settings I changed: voice_collect_seconds 6.0, endpoint_silence_ms 1500, hot_window_seconds 12, llm_chat_timeout_sec 40, llm_tools_timeout_sec 50, tool_selection_strategy "all", wake_aliases (29 entries: 12 defaults + 17, see D17 and D18). What voice_collect_seconds and endpoint_silence_ms do exactly is undocumented; the log shows a fixed wait of about voice_collect_seconds + 1 s before the plan.
- Relay (port 8787) knobs: RELAY_FIRST_BYTE_S (5), RELAY_BACKUP_MODELS (gemini-3.1-flash-lite), RELAY_BANTER (30). It never logs what was said; `kind` is only the first 60 chars of Jarvis's own fixed prompt. Tests that call it add lines to relay_log.jsonl (git-ignored).
