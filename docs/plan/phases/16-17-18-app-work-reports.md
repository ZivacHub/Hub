## App contract (16.1)
Written 2026-11-17 by the 16.1 helper. The Hub app is an Electron 44.9.3 program that only WRAPS the dashboard page; tools/dashboard/ is unchanged.

**Files**
- `tools/app/package.json` (+ `package-lock.json`): name hub-app, private, ESM, `main: main.mjs`, electron 44.9.3 exact (dev dependency). Scripts: `postinstall` = `install-electron` (Electron 44 no longer downloads its program by itself on `npm install`; this makes it do so), `start` = `electron .`, `selftest` = `node selftest.mjs`.
- `tools/app/main.mjs`: the main process (functions below). `tools/app/lib/rules.mjs`: pure rules (port, server flags, Hub origin, claude:// allow-list). `tools/app/lib/server.mjs`: findOrStartServer, stopServer, pageAnswers (spawn and fetch injectable). `tools/app/selftest.mjs` (plain Node runner) and `tools/app/selftest-inapp.mjs` (runs inside the app in self-test mode only).
- `Start Hub App.bat` (project root): opens the app (`start "" ...\electron.exe ...\tools\app`, console closes at once); if Electron is not installed it says "Run npm install in tools\app first." and waits.
- Git-ignored: `tools/app/node_modules/` (about 383 MB, Electron program 369 MB), `tools/app/out/`, `logs/hub_app_server.log` (output of a dashboard the app started).

**Environment variables** (nothing else from the environment or the command line reaches the server command)
| Variable | Meaning |
|---|---|
| `HUB_PORT` | dashboard port, default 4780; not a whole number 1..65535 = plain error dialog. Passed on to a dashboard the app starts. |
| `HUB_APP_ARGS` | extra dashboard flags, space separated; only `--word` or `--word=value` kept; `--open` and `--selftest` dropped. Example: `--demo`. |
| `HUB_APP_SELFTEST` | `1` = self-test mode (only with HUB_PORT=4792 and HUB_APP_ARGS=--demo; own throw-away profile folder in the temp folder). |
| `HUB_APP_DEVTOOLS` | `1` = developer tools allowed; otherwise they cannot be opened. |
| `HUB_APP_SHOT` | self-test only: path of a PNG screenshot of the window. |

**findOrStartServer** (lib/server.mjs) returns one of: `{ ok: true, ownsServer: false, child: null, url }` (GET http://127.0.0.1:PORT/ already answered 200 within 2 s: attach, start nothing); `{ ok: true, ownsServer: true, child, pid, url }` (started `node tools/dashboard/server.mjs <HUB_APP_ARGS>`, shell off, hidden, cwd = Hub folder, output to logs/hub_app_server.log, page answered; polled every 250 ms for up to 30 s); `{ ok: false, reason, message }` with reason `node-missing` ("Node.js was not found on this PC, so the Hub cannot start."), `no-server-file`, `exited`, `timeout`, `spawn-failed`; `message` is plain words shown in a dialog, never a stack trace. Quit stops the server ONLY when ownsServer is true, with `child.kill()` only (its own child processes are 16.3's business).

**Security settings**: one window 1360x900 (smallest 380x600), title "Hub", no menu bar, background matching the page. webPreferences: contextIsolation true, nodeIntegration false, sandbox true, webSecurity true, no preload, webviewTag false, spellcheck false, devTools only with HUB_APP_DEVTOOLS=1. Navigation: the window only shows pages whose origin is exactly `http://127.0.0.1:PORT` (not localhost, not another port); will-navigate, will-redirect and sub-frame navigations elsewhere are refused; every new-window request is refused (also for Hub pages: one window). Webviews blocked. All permission requests and checks refused (notifications, microphone, camera, location, devices); downloads refused. The page's own Content-Security-Policy is untouched; normal mode injects no script or style (only the self-test runs checks inside the page).

**claude:// allow-list**: a navigation or new-window request whose URL starts with exactly `claude://claude.ai/epitaxy/local_`, `claude://code/new?` or `claude://resume?session=` (with something after the prefix, no spaces or control characters, at most 4096 characters) is passed to `shell.openExternal` and the window stays on the Hub. Anything else that is not the Hub origin is refused and never opened. Known effect: the "Running · port N" link on a project card (opens another 127.0.0.1 port in a new tab in the browser) does nothing in the app; 16.2 or 16.3 decides whether such links go to the default browser.

**Run**: double-click `Start Hub App.bat`, or `npm start` in tools/app. Install on a new PC: `npm install` in tools/app. Self-test: `node tools/app/selftest.mjs` (or `npm run selftest` in tools/app); exit code 0 = pass; a Hub window with sample data shows for about 20 s and closes itself; add `HUB_APP_SHOT=<path.png>` for a screenshot.

**Hooks for 16.2 and 16.3** (all in main.mjs; `state` = `{ port, server, window, quitting, stopped }`)
- `createWindow({ port, openExternal, showInactive })`: 16.2 adds the hide-on-close (D51) here, on the window's `close` event.
- `installQuitHooks()`: today `window-all-closed` quits (16.1). 16.2 replaces that with "keep running in the tray"; the tray's Quit calls `app.quit()`, and `before-quit` then runs the stops.
- `stopOwnedServer()`: the stop that runs on a real quit. 16.3 adds "stop every project the Hub started" (D53) next to it in the `before-quit` handler.
- `startHub()`: start-up order (lock the session, findOrStartServer, createWindow). 16.2 adds `app.requestSingleInstanceLock()` before it and the tray after it; 16.3 adds the start-with-Windows switch (app.setLoginItemSettings) and the `--boot` behaviour.
- `lockDownSession(session)` and `lockDownNavigation(webContents, { port, openExternal })`: reuse for any further window; do not loosen them.

## Tray contract (16.2)
Written 2026-11-18 by the 16.2 helper. Files: `tools/app/lib/tray.mjs` (the icon), `tools/app/lib/traymenu.mjs` (menu as plain data), `tools/app/assets/` (icon files drawn by `tools/app/make-icons.mjs`, plain Node, run once; PNGs are checked in), changes in `main.mjs`, `lib/rules.mjs`.
- **Icon**: rounded square in dashboard blue (#0b5f8a) with a white H: `icon-16/32/48/256.png`, `icon.png` (256; window and taskbar), `tray-needs.png` (32, amber dot, for a later "needs you" state: `setTrayNeedsYou(true)` in tray.mjs switches to it, not used yet).
- **Tray**: `installTray()` (main.mjs) creates it after the window; tooltip "Hub"; left click and double click = `showHub()`; menu = "Open Hub", separator, "Quit Hub". Hook for 16.3: `setTrayMenuExtras([menuItem, ...])` (exported from main.mjs and lib/tray.mjs) puts items between "Open Hub" and "Quit Hub" and rebuilds the menu; `getTrayTemplate()` returns the last template. Start-with-Windows is NOT implemented (16.3).
- **Hide on close (D51)**: the window's `close` event is prevented and the window hidden unless `state.quitting` is true. `state.quitting` is set by `quitHub()` (the menu's Quit Hub), by app `before-quit`, and by the window's `session-end` (Windows shutdown). `window-all-closed` has an empty listener: the Hub stays alive. `before-quit` also destroys the tray; `stopOwnedServer()` is unchanged (16.3 adds its project stops there, D53).
- **showHub()**: re-creates the window if destroyed (uses `state.port` and `state.openExternal`), restores if minimized, shows, focuses. `quitHub()` = real quit.
- **Single instance**: `app.requestSingleInstanceLock()` right after the profile path is set; a second start calls `app.exit(0)` at once and the first gets `second-instance` and runs `showHub()` (only once `state.server` is set, i.e. after start-up). The lock is per profile folder, so the self-test (own temp profile) never meets a real Hub.
- **Links**: `isOtherLocalPortLink(url, hubPort)` (rules.mjs): http on 127.0.0.1 or localhost, explicit port 1024-65535, not the Hub's port, no user name or password. Such a link (the "Running · port N" link) is passed to `state.openExternal` (default browser) like a claude:// link; the window stays on the Hub. Everything else stays refused.
- **Self-test**: `node tools/app/selftest.mjs`, now 14 checks in the runner and 59 in the app; the runner starts the second electron.exe when the app prints `READY_FOR_SECOND_INSTANCE`. Not provable by a test: that the icon is visible in the Windows hidden-icons area (only `tray.getBounds()` and `isDestroyed()` are checked).

## Projects and start-up contract (16.3)
Written 2026-11-18 by the 16.3 helper (D52, D53). New files: `tools/app/lib/projects.mjs` (stop what the Hub started), `tools/app/lib/startup.mjs` (--hidden, the icon menu lines). Changed: `main.mjs`, `lib/rules.mjs` (--boot dropped from HUB_APP_ARGS), `lib/server.mjs` (comment only), `selftest.mjs`, `selftest-inapp.mjs`, `Start Hub App.bat` (repaired: the committed 16.1 file had lost every backslash in its paths, so it could not find electron.exe; now `tools\app\node_modules\electron\dist\electron.exe "%~dp0tools\app"` again, CRLF, plus two comment lines). tools/dashboard/ is unchanged.
- **Quit stops what the Hub started (D53).** A real quit ("Quit Hub", `app.quit()`) runs `runQuitSequence()` (main.mjs) once from `before-quit`: `quitSequence` (lib/projects.mjs) first calls `stopHubProjects({ port, fetchFn, limitMs: 20000, log })`, then `stopOwnedServer()` only if the app started the dashboard. `stopHubProjects` reads GET `/api/runtime` (`{ demo, items: [{ id, status, startedByHub, ... }] }`), takes every item with `startedByHub: true` (and an id of letters, digits, `-`, `_`), gets the token from GET `/api/session`, and posts `{ action: "stop", id, confirm: true }` to `/api/action` one by one with `Origin: http://127.0.0.1:PORT`, `X-Hub-Token`, `Content-Type: application/json`, exactly like the page. The dashboard does the stop itself (taskkill in control.mjs); the app never kills a project. With an ATTACHED dashboard the projects it started are stopped too; the dashboard process is left running. One line per project in `logs/hub_app.log` (git-ignored; no token): `stop <id> ok` / `stop <id> failed: <reason>`; also one line when nothing is to be stopped or the dashboard is gone. A failing project never blocks the rest. Limits: 20 s for the projects (each request bounded by what is left), 8 s for the dashboard stop, and a backstop `app.exit(0)` after 35 s: quitting never hangs. Windows shutdown/log-off (`before-quit` is not emitted then): the window's `session-end` starts the same sequence, best effort (Windows may end the app first; it ends every program then anyway).
- **Hidden start.** The exact command-line element `--hidden` (`parseAppFlags(process.argv)`, not an env variable) gives `startPlan()` = no visible window (the window is created hidden so `session-end` can reach it; "Open Hub" shows it) and server flags + `--boot`. `--boot` only matters when the app starts its own dashboard (findOrStartServer uses the flags only when it spawns); with an attached dashboard nothing is started. A normal start (double click) shows the window and never has `--boot`; `parseServerArgs` drops `--boot` (and `--boot=...`) from HUB_APP_ARGS. A second start with `--hidden` while the Hub runs does not pop the window up; a second start without it shows the window (16.2).
- **Icon menu** (via `setTrayMenuExtras`, `makeStartupMenu` in lib/startup.mjs): `Open Hub` / `Start with Windows` (checkbox) / `Projects running: N` (disabled; status "running" from /api/runtime; "unknown (dashboard not answering)" when it does not answer) / `Old start-up entry found: run Remove Hub Autostart.bat` (disabled, only when `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Hub Dashboard.lnk` exists; existence check only, nothing in the Startup folder is ever created, changed or deleted) / `Quit Hub`. Count and old-entry check refresh every 15 s and when the mouse enters the icon; the menu is rebuilt only when a line changes.
- **Start with Windows.** Read with `app.getLoginItemSettings({ path, args })`, written ONLY by Ivan's click with `app.setLoginItemSettings({ openAtLogin, path, args, name })`, the same options for both: `path = process.execPath` (electron.exe), `args = [<tools/app folder>, "--hidden"]` (the folder is put in quotes if it ever contains a space; Electron joins args with spaces without quoting), `name = "Hub"`. The box shows ticked only when `openAtLogin` is true and Windows will really launch it (`executableWillLaunchAtLogin` is not false: an entry switched off in Task Manager shows unticked; a click then switches it on again). Each change is one line in logs/hub_app.log. Self-test mode uses `fakeLoginItems` and replaces `app.setLoginItemSettings` with a guard that throws, so no test can write the registry.
- **Per-project "Start with PC"** is unchanged: the dashboard page's switch + data/hub_state.json `autostart`; `--boot` starts those 20 s after the dashboard is up.
- **Old route.** Install Hub Autostart.bat -> hub-boot.vbs -> `Start Hub Dashboard.bat boot` stays on disk, unchanged. If both exist they do not double-start: whichever dashboard is first on 4780 wins (the other exits at once on "port in use", before its --boot timer), the app attaches to it, and control.mjs refuses to start a project whose port already answers. The menu line tells Ivan to remove the old one.
- **Self-test**: `node tools/app/selftest.mjs`: 47 checks in the runner (33 new: fake dashboard on a spare port for the quit, --hidden and --boot, the menu with a fake login item, a code check that the real setter is only in the non-self-test branch) and 73 in the app (was 59); the runner now starts the app as `electron.exe tools/app --hidden`, and the app ends with a real quit (Quit Hub) that asks the sample dashboard (4792 --demo) to stop clip-studio and manager; it answers "Sample data mode: the buttons are switched off.", which is logged and handled. The self-test's app log is `%TEMP%\hub-app-selftest\hub_app.log`.
